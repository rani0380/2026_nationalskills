# 02_1과제_1등 상세 풀이

대상 폴더: `select/1과제/02_1과제_1등`

이 과제는 `Korea Skills Concert` 예약 서비스를 AWS 위에 구축하는 문제입니다. 단순히 리소스를 만드는 문제가 아니라, 채점 스크립트가 정해진 이름과 경로를 조회하므로 **리소스명, 태그, 경로, 헤더, KMS alias**를 정확히 맞추는 것이 가장 중요합니다.

## 0. 전체 아키텍처

사용자 요청 흐름은 다음과 같이 잡습니다.

1. 사용자는 CloudFront 도메인으로 접속합니다.
2. `/` 요청은 S3의 `web/main/index.html`로 전달됩니다.
3. `/main.jpeg` 요청은 S3의 `web/main/main.jpeg`로 전달됩니다.
4. `/book` POST 요청은 CloudFront -> ALB -> EKS book Pod로 전달되어 DynamoDB에 예약 정보를 저장합니다.
5. `/book?concert_name=...` GET 요청은 CloudFront -> ALB -> Lambda로 전달되어 DynamoDB에서 예약 정보를 조회합니다.
6. ALB에 직접 접근하면 `403 Forbidden`을 반환합니다.
7. EKS의 시스템/모니터링 컴포넌트는 addon nodegroup, book 애플리케이션은 app nodegroup에서만 동작합니다.

채점 스크립트는 다음 값을 직접 확인합니다.

| 영역 | 채점에서 찾는 값 |
|---|---|
| VPC | `wskorea26-vpc`, `172.16.0.0/16` |
| Subnet | `wskorea26-pub-subnet-c`, `wskorea26-pub-subnet-d`, `wskorea26-priv-subnet-c`, `wskorea26-priv-subnet-d` |
| Route Table | `wskorea26-public-rtb`, `wskorea26-private-rtb-c`, `wskorea26-private-rtb-d` |
| S3 | `wskorea26-concert-bucket-`로 시작하는 버킷 |
| S3 Object | `web/main/index.html`, `web/main/main.jpeg` |
| S3 KMS alias | `alias/wskorea26-s3-key` |
| ECR | `wskorea26-book-repo`, image tag `stable` |
| DynamoDB | `wskorea26-data-table`, PK `client_id` |
| DynamoDB KMS alias | `alias/wskorea26-dynamodb-key` |
| EKS | `wskorea26-cluster`, version `1.35` |
| EKS KMS alias | `alias/wskorea26-eks-key` |
| NodeGroup | `wskorea26-addon-ng`, `wskorea26-app-ng` |
| Node label | addon: `node-type=addon`, app: `node-type=app` |
| Namespace | `wskorea26` |
| Lambda | `wskorea26-book-lambda`, env `TABLE_NAME=wskorea26-data-table` |
| ALB | `wskorea26-book-alb`, internet-facing, HTTP 80 |
| CloudFront Comment | `wskorea26-concert-cf` |
| CloudFront Header | `X-Origin-Verify: wskorea26-cf`, `wskorea26-s3-access` |
| Grafana | service `grafana` in namespace `monitoring`, dashboard path `/d/wskorea26/wskorea26-monitoring` |

## 1. 공통 변수 설정

```bash
export AWS_REGION=ap-northeast-2
export ACCOUNT_ID=$(aws sts get-caller-identity --query Account --output text)
export NO=<비번호>
export BUCKET=wskorea26-concert-bucket-${NO}

aws configure set region ${AWS_REGION}
aws sts get-caller-identity
```

비번호가 `12`라면 버킷명은 예를 들어 `wskorea26-concert-bucket-12`처럼 만듭니다. 채점 스크립트는 `starts_with(Name, 'wskorea26-concert-bucket-')`로 첫 번째 버킷을 찾으므로 같은 prefix의 불필요한 버킷을 여러 개 만들지 않는 것이 좋습니다.

## 2. KMS 키 먼저 만들기

이 과제는 S3, DynamoDB, EKS Secret 암호화에서 KMS alias를 확인합니다. 리소스를 만들기 전에 키를 먼저 준비합니다.

```bash
S3_KEY_ID=$(aws kms create-key --description wskorea26-s3-key --query KeyMetadata.KeyId --output text)
aws kms create-alias --alias-name alias/wskorea26-s3-key --target-key-id ${S3_KEY_ID}

DDB_KEY_ID=$(aws kms create-key --description wskorea26-dynamodb-key --query KeyMetadata.KeyId --output text)
aws kms create-alias --alias-name alias/wskorea26-dynamodb-key --target-key-id ${DDB_KEY_ID}

EKS_KEY_ID=$(aws kms create-key --description wskorea26-eks-key --query KeyMetadata.KeyId --output text)
aws kms create-alias --alias-name alias/wskorea26-eks-key --target-key-id ${EKS_KEY_ID}
```

확인:

```bash
aws kms list-aliases --query "Aliases[?starts_with(AliasName, 'alias/wskorea26')].[AliasName,TargetKeyId]" --output table
```

## 3. 네트워크 구성

### 3.1 VPC와 Subnet

Reference01 그대로 구성합니다.

| 리소스 | CIDR | 라우팅 |
|---|---|---|
| `wskorea26-vpc` | `172.16.0.0/16` | - |
| `wskorea26-pub-subnet-c` | `172.16.1.0/24` | `wskorea26-public-rtb` -> IGW |
| `wskorea26-pub-subnet-d` | `172.16.2.0/24` | `wskorea26-public-rtb` -> IGW |
| `wskorea26-priv-subnet-c` | `172.16.201.0/24` | `wskorea26-private-rtb-c` -> NAT c |
| `wskorea26-priv-subnet-d` | `172.16.202.0/24` | `wskorea26-private-rtb-d` -> NAT d |

```bash
VPC_ID=$(aws ec2 create-vpc \
  --cidr-block 172.16.0.0/16 \
  --tag-specifications 'ResourceType=vpc,Tags=[{Key=Name,Value=wskorea26-vpc}]' \
  --query Vpc.VpcId --output text)

aws ec2 modify-vpc-attribute --vpc-id ${VPC_ID} --enable-dns-hostnames
aws ec2 modify-vpc-attribute --vpc-id ${VPC_ID} --enable-dns-support
```

AZ 이름은 계정마다 다를 수 있으므로 먼저 확인합니다.

```bash
aws ec2 describe-availability-zones \
  --query "AvailabilityZones[?State=='available'].ZoneName" \
  --output text
```

예시에서는 `ap-northeast-2c`, `ap-northeast-2d`를 사용합니다.

```bash
PUB_C=$(aws ec2 create-subnet --vpc-id ${VPC_ID} --cidr-block 172.16.1.0/24 --availability-zone ap-northeast-2c \
  --tag-specifications 'ResourceType=subnet,Tags=[{Key=Name,Value=wskorea26-pub-subnet-c}]' --query Subnet.SubnetId --output text)
PUB_D=$(aws ec2 create-subnet --vpc-id ${VPC_ID} --cidr-block 172.16.2.0/24 --availability-zone ap-northeast-2d \
  --tag-specifications 'ResourceType=subnet,Tags=[{Key=Name,Value=wskorea26-pub-subnet-d}]' --query Subnet.SubnetId --output text)
PRIV_C=$(aws ec2 create-subnet --vpc-id ${VPC_ID} --cidr-block 172.16.201.0/24 --availability-zone ap-northeast-2c \
  --tag-specifications 'ResourceType=subnet,Tags=[{Key=Name,Value=wskorea26-priv-subnet-c}]' --query Subnet.SubnetId --output text)
PRIV_D=$(aws ec2 create-subnet --vpc-id ${VPC_ID} --cidr-block 172.16.202.0/24 --availability-zone ap-northeast-2d \
  --tag-specifications 'ResourceType=subnet,Tags=[{Key=Name,Value=wskorea26-priv-subnet-d}]' --query Subnet.SubnetId --output text)
```

ALB Controller를 사용할 경우 subnet discovery를 위해 태그를 추가해두면 좋습니다.

```bash
aws ec2 create-tags --resources ${PUB_C} ${PUB_D} --tags Key=kubernetes.io/role/elb,Value=1
aws ec2 create-tags --resources ${PRIV_C} ${PRIV_D} --tags Key=kubernetes.io/role/internal-elb,Value=1
```

### 3.2 IGW, NAT Gateway, Route Table

```bash
IGW_ID=$(aws ec2 create-internet-gateway \
  --tag-specifications 'ResourceType=internet-gateway,Tags=[{Key=Name,Value=book-igw}]' \
  --query InternetGateway.InternetGatewayId --output text)
aws ec2 attach-internet-gateway --vpc-id ${VPC_ID} --internet-gateway-id ${IGW_ID}

PUBLIC_RTB=$(aws ec2 create-route-table --vpc-id ${VPC_ID} \
  --tag-specifications 'ResourceType=route-table,Tags=[{Key=Name,Value=wskorea26-public-rtb}]' \
  --query RouteTable.RouteTableId --output text)
aws ec2 create-route --route-table-id ${PUBLIC_RTB} --destination-cidr-block 0.0.0.0/0 --gateway-id ${IGW_ID}
aws ec2 associate-route-table --route-table-id ${PUBLIC_RTB} --subnet-id ${PUB_C}
aws ec2 associate-route-table --route-table-id ${PUBLIC_RTB} --subnet-id ${PUB_D}
```

NAT는 private subnet의 EKS node가 ECR, CloudWatch, AWS API에 접근하기 위해 필요합니다.

```bash
EIP_C=$(aws ec2 allocate-address --domain vpc --query AllocationId --output text)
EIP_D=$(aws ec2 allocate-address --domain vpc --query AllocationId --output text)

NGW_C=$(aws ec2 create-nat-gateway --subnet-id ${PUB_C} --allocation-id ${EIP_C} \
  --tag-specifications 'ResourceType=natgateway,Tags=[{Key=Name,Value=book-ngw-c}]' \
  --query NatGateway.NatGatewayId --output text)
NGW_D=$(aws ec2 create-nat-gateway --subnet-id ${PUB_D} --allocation-id ${EIP_D} \
  --tag-specifications 'ResourceType=natgateway,Tags=[{Key=Name,Value=book-ngw-d}]' \
  --query NatGateway.NatGatewayId --output text)

aws ec2 wait nat-gateway-available --nat-gateway-ids ${NGW_C} ${NGW_D}
```

```bash
PRIV_RTB_C=$(aws ec2 create-route-table --vpc-id ${VPC_ID} \
  --tag-specifications 'ResourceType=route-table,Tags=[{Key=Name,Value=wskorea26-private-rtb-c}]' \
  --query RouteTable.RouteTableId --output text)
aws ec2 create-route --route-table-id ${PRIV_RTB_C} --destination-cidr-block 0.0.0.0/0 --nat-gateway-id ${NGW_C}
aws ec2 associate-route-table --route-table-id ${PRIV_RTB_C} --subnet-id ${PRIV_C}

PRIV_RTB_D=$(aws ec2 create-route-table --vpc-id ${VPC_ID} \
  --tag-specifications 'ResourceType=route-table,Tags=[{Key=Name,Value=wskorea26-private-rtb-d}]' \
  --query RouteTable.RouteTableId --output text)
aws ec2 create-route --route-table-id ${PRIV_RTB_D} --destination-cidr-block 0.0.0.0/0 --nat-gateway-id ${NGW_D}
aws ec2 associate-route-table --route-table-id ${PRIV_RTB_D} --subnet-id ${PRIV_D}
```

### 4.2 객체 업로드

문제지의 Object Path가 `/web/main/`이므로 정확히 이 prefix로 업로드합니다.

```bash
aws s3 cp index.html s3://${BUCKET}/web/main/index.html \
  --sse aws:kms \
  --sse-kms-key-id alias/wskorea26-s3-key \
  --content-type text/html

aws s3 cp main.jpeg s3://${BUCKET}/web/main/main.jpeg \
  --sse aws:kms \
  --sse-kms-key-id alias/wskorea26-s3-key \
  --content-type image/jpeg
```

채점 스크립트는 `head-object`로 `SSEKMSKeyId`를 읽고 그 key id의 alias가 `alias/wskorea26-s3-key`인지 확인합니다.

```bash
for key in web/main/index.html web/main/main.jpeg; do
  aws s3api head-object --bucket ${BUCKET} --key $key \
    --query "[Key,SSEKMSKeyId,ContentType]" --output table
done
```

## 5. DynamoDB

문제지에는 PK가 `client_id(S)`라고 되어 있습니다. GET 조회는 `concert_name` 최신순 정렬이 필요하므로 실전 풀이에서는 GSI를 추가하는 편이 안정적입니다.

| 항목 | 값 |
|---|---|
| Table | `wskorea26-data-table` |
| PK | `client_id` String |
| 권장 GSI | `concert-created-index` |
| GSI PK | `concert_name` String |
| GSI SK | `created_at` String |
| 과금 | `PAY_PER_REQUEST` |
| 암호화 | KMS `alias/wskorea26-dynamodb-key` |
| 삭제 방지 | Enabled |

```bash
aws dynamodb create-table \
  --table-name wskorea26-data-table \
  --attribute-definitions \
    AttributeName=client_id,AttributeType=S \
    AttributeName=concert_name,AttributeType=S \
    AttributeName=created_at,AttributeType=S \
  --key-schema AttributeName=client_id,KeyType=HASH \
  --global-secondary-indexes '[
    {
      "IndexName": "concert-created-index",
      "KeySchema": [
        {"AttributeName": "concert_name", "KeyType": "HASH"},
        {"AttributeName": "created_at", "KeyType": "RANGE"}
      ],
      "Projection": {"ProjectionType": "ALL"}
    }
  ]' \
  --billing-mode PAY_PER_REQUEST \
  --sse-specification Enabled=true,SSEType=KMS,KMSMasterKeyId=alias/wskorea26-dynamodb-key \
  --deletion-protection-enabled
```

확인:

```bash
aws dynamodb describe-table --table-name wskorea26-data-table \
  --query "Table.[TableName,KeySchema[0].[AttributeName,KeyType],DeletionProtectionEnabled,SSEDescription.KMSMasterKeyArn]" \
  --output table
```

## 6. ECR와 book 이미지

### 6.1 Dockerfile

제공 파일은 수정하지 말고 컨테이너에 그대로 넣습니다.

```dockerfile
FROM public.ecr.aws/amazonlinux/amazonlinux:2023

CMD ["/app/book"]
```

### 6.2 ECR 생성과 push

```bash
aws ecr create-repository \
  --repository-name wskorea26-book-repo \
  --image-scanning-configuration scanOnPush=true \
  --encryption-configuration encryptionType=KMS,kmsKey=alias/wskorea26-s3-key

aws ecr get-login-password --region ${AWS_REGION} \
  | docker login --username AWS --password-stdin ${ACCOUNT_ID}.dkr.ecr.${AWS_REGION}.amazonaws.com

docker build -t wskorea26-book-repo:stable .
docker tag wskorea26-book-repo:stable ${ACCOUNT_ID}.dkr.ecr.${AWS_REGION}.amazonaws.com/wskorea26-book-repo:stable
docker push ${ACCOUNT_ID}.dkr.ecr.${AWS_REGION}.amazonaws.com/wskorea26-book-repo:stable
```

주의: 채점 스크립트는 ECR 암호화 타입만 확인합니다. 그래도 문제 요구사항상 이미지는 KMS로 암호화하는 것이 좋습니다. 별도 ECR KMS 키를 만들면 더 깔끔하지만, 채점 스크립트는 alias까지 확인하지 않습니다.

확인:

```bash
aws ecr describe-repositories \
  --query "repositories[?repositoryName=='wskorea26-book-repo'].[repositoryName,imageScanningConfiguration.scanOnPush,encryptionConfiguration.encryptionType]" \
  --output table

aws ecr describe-images \
  --repository-name wskorea26-book-repo \
  --image-ids imageTag=stable \
  --query "imageDetails[0].imageTags" \
  --output text
```

## 7. EKS Cluster와 NodeGroup

문제 요구사항:

| 항목 | 값 |
|---|---|
| Cluster | `wskorea26-cluster` |
| Version | `1.35` |
| Subnet | `wskorea26-priv-subnet-c`, `wskorea26-priv-subnet-d` |
| Secret encryption | `alias/wskorea26-eks-key` |
| Addon NodeGroup | `wskorea26-addon-ng`, `t3.medium`, tag `Name=wskorea26-addon-node`, label `node-type=addon` |
| App NodeGroup | `wskorea26-app-ng`, `t3.medium`, tag `Name=wskorea26-app-node`, label `node-type=app` |

### 7.1 eksctl 예시

`cluster.yaml`:

```yaml
apiVersion: eksctl.io/v1alpha5
kind: ClusterConfig

metadata:
  name: wskorea26-cluster
  region: ap-northeast-2
  version: "1.35"

vpc:
  id: "<VPC_ID>"
  subnets:
    private:
      ap-northeast-2c:
        id: "<PRIV_C_SUBNET_ID>"
      ap-northeast-2d:
        id: "<PRIV_D_SUBNET_ID>"

cloudWatch:
  clusterLogging:
    enableTypes:
      - api
      - audit
      - authenticator
      - controllerManager
      - scheduler

secretsEncryption:
  keyARN: "<EKS_KMS_KEY_ARN>"

iam:
  withOIDC: true

managedNodeGroups:
  - name: wskorea26-addon-ng
    instanceType: t3.medium
    desiredCapacity: 2
    minSize: 2
    maxSize: 2
    privateNetworking: true
    labels:
      node-type: addon
    tags:
      Name: wskorea26-addon-node
    taints:
      - key: dedicated
        value: addon
        effect: NoSchedule

  - name: wskorea26-app-ng
    instanceType: t3.medium
    desiredCapacity: 2
    minSize: 2
    maxSize: 2
    privateNetworking: true
    labels:
      node-type: app
    tags:
      Name: wskorea26-app-node
    taints:
      - key: dedicated
        value: app
        effect: NoSchedule
```

생성:

```bash
eksctl create cluster -f cluster.yaml
aws eks update-kubeconfig --region ap-northeast-2 --name wskorea26-cluster
kubectl create namespace wskorea26
kubectl create namespace monitoring
```

채점 스크립트는 kube-system에서 `aws-node`, `kube-proxy`를 제외한 Pod들이 addon node에 있는지 확인합니다. 따라서 CoreDNS, AWS Load Balancer Controller, Metrics Server, Grafana/Prometheus 계열은 addon node에 배치해야 합니다.

Addon에 배포할 컴포넌트에는 다음을 붙입니다.

```yaml
nodeSelector:
  node-type: addon
tolerations:
  - key: dedicated
    operator: Equal
    value: addon
    effect: NoSchedule
```

Book 앱에는 다음을 붙입니다.

```yaml
nodeSelector:
  node-type: app
tolerations:
  - key: dedicated
    operator: Equal
    value: app
    effect: NoSchedule
```

## 8. IAM 권한 구성

### 8.1 book Pod 권한

book 앱은 DynamoDB에 예약 정보를 저장해야 합니다.

필요 권한:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "dynamodb:PutItem",
        "dynamodb:UpdateItem",
        "dynamodb:GetItem",
        "dynamodb:Query",
        "dynamodb:Scan"
      ],
      "Resource": [
        "arn:aws:dynamodb:ap-northeast-2:<ACCOUNT_ID>:table/wskorea26-data-table",
        "arn:aws:dynamodb:ap-northeast-2:<ACCOUNT_ID>:table/wskorea26-data-table/index/*"
      ]
    }
  ]
}
```

IRSA 또는 EKS Pod Identity를 사용합니다. 대회 환경에서 설정 시간이 부족하면 node role에 임시로 권한을 붙일 수 있지만, 최소 권한 원칙 관점에서는 service account 전용 role이 더 좋습니다.

## 9. Kubernetes book 배포

문제지의 앱 설명:

| 항목 | 값 |
|---|---|
| Env | `AWS_REGION`, `TABLE_NAME` |
| Port | `8080` |
| Health | `/health` |
| POST | `/v1/book` |

`book-deploy.yaml`:

```yaml
apiVersion: v1
kind: ServiceAccount
metadata:
  name: book-sa
  namespace: wskorea26
  annotations:
    eks.amazonaws.com/role-arn: arn:aws:iam::<ACCOUNT_ID>:role/wskorea26-book-pod-role
---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: book
  namespace: wskorea26
spec:
  replicas: 2
  selector:
    matchLabels:
      app: book
  template:
    metadata:
      labels:
        app: book
    spec:
      serviceAccountName: book-sa
      nodeSelector:
        node-type: app
      tolerations:
        - key: dedicated
          operator: Equal
          value: app
          effect: NoSchedule
      containers:
        - name: book
          image: <ACCOUNT_ID>.dkr.ecr.ap-northeast-2.amazonaws.com/wskorea26-book-repo:stable
          imagePullPolicy: Always
          ports:
            - containerPort: 8080
          env:
            - name: AWS_REGION
              value: ap-northeast-2
            - name: TABLE_NAME
              value: wskorea26-data-table
          readinessProbe:
            httpGet:
              path: /health
              port: 8080
            initialDelaySeconds: 10
            periodSeconds: 10
          livenessProbe:
            httpGet:
              path: /health
              port: 8080
            initialDelaySeconds: 20
            periodSeconds: 20
---
apiVersion: v1
kind: Service
metadata:
  name: book-svc
  namespace: wskorea26
spec:
  type: NodePort
  selector:
    app: book
  ports:
    - name: http
      port: 80
      targetPort: 8080
```

## 10. Lambda 조회 함수

문제지에서는 Python 3.14를 요구합니다. 계정에서 해당 런타임이 지원되면 `python3.14`를 사용하고, 지원되지 않는 환경에서는 심사 기준에 맞춰 제공 런타임 중 가장 가까운 Python 3.x를 사용해야 합니다.

채점 스크립트는 다음만 직접 확인합니다.

```bash
aws lambda get-function-configuration \
  --function-name wskorea26-book-lambda \
  --query "[FunctionName,Runtime,Environment.Variables.TABLE_NAME]" \
  --output text
```

Lambda는 ALB 이벤트를 받는다고 가정하고 작성합니다. 공개 요청은 `/book?concert_name=...`로 들어오지만 내부 요구사항은 `/reserv-query`입니다. 안전하게 두 경로 모두 처리하게 만들면 좋습니다.

`lambda_function.py`:

```python
import json
import os
from decimal import Decimal

import boto3
from boto3.dynamodb.conditions import Key

REGION = os.environ.get("AWS_REGION", "ap-northeast-2")
TABLE_NAME = os.environ["TABLE_NAME"]
INDEX_NAME = os.environ.get("INDEX_NAME", "concert-created-index")

dynamodb = boto3.resource("dynamodb", region_name=REGION)
table = dynamodb.Table(TABLE_NAME)


def _json_default(value):
    if isinstance(value, Decimal):
        return int(value) if value % 1 == 0 else float(value)
    raise TypeError(type(value).__name__)


def _alb_response(status_code, body):
    return {
        "statusCode": status_code,
        "statusDescription": f"{status_code}",
        "isBase64Encoded": False,
        "headers": {
            "content-type": "application/json; charset=utf-8"
        },
        "body": json.dumps(body, ensure_ascii=False, default=_json_default),
    }


def handler(event, context):
    params = event.get("queryStringParameters") or {}
    concert_name = params.get("concert_name")

    if not concert_name:
        return _alb_response(400, {"error": "concert_name is required"})

    try:
        response = table.query(
            IndexName=INDEX_NAME,
            KeyConditionExpression=Key("concert_name").eq(concert_name),
            ScanIndexForward=False,
        )
        items = response.get("Items", [])
    except Exception:
        # GSI가 없다면 마지막 방어선으로 scan을 사용한다.
        response = table.scan(
            FilterExpression=Key("concert_name").eq(concert_name)
        )
        items = sorted(
            response.get("Items", []),
            key=lambda item: item.get("created_at", ""),
            reverse=True,
        )

    return _alb_response(200, items)
```

배포:

```bash
zip function.zip lambda_function.py

aws lambda create-function \
  --function-name wskorea26-book-lambda \
  --runtime python3.14 \
  --handler lambda_function.handler \
  --zip-file fileb://function.zip \
  --role arn:aws:iam::<ACCOUNT_ID>:role/wskorea26-book-lambda-role \
  --timeout 10 \
  --environment Variables="{AWS_REGION=ap-northeast-2,TABLE_NAME=wskorea26-data-table,INDEX_NAME=concert-created-index}"
```

Lambda role에는 DynamoDB `Query`, `Scan`, CloudWatch Logs 권한을 부여합니다.

## 11. ALB 구성

이 과제의 가장 까다로운 부분입니다.

채점 요구:

1. ALB 이름은 `wskorea26-book-alb`
2. scheme은 `internet-facing`
3. listener는 HTTP 80
4. CloudFront를 통하지 않은 `http://<ALB_DNS>/book` 요청은 `403`
5. CloudFront로 들어온 `/book` POST는 예약 저장
6. CloudFront로 들어온 `/book?concert_name=...` GET은 예약 조회

### 11.1 추천 경로 처리 방식

외부 공개 URL은 `/book`으로 유지하고, CloudFront Function에서 내부 경로를 바꿉니다.

| 사용자 요청 | CloudFront Function 내부 rewrite | ALB target |
|---|---|---|
| `POST /book` | `/v1/book` | EKS book service |
| `GET /book?concert_name=...` | `/reserv-query` | Lambda target group |

이렇게 하면 제공 앱의 `/v1/book`, Lambda 요구사항의 `/reserv-query`를 모두 살릴 수 있습니다.

### 11.2 ALB Listener Rule 설계

ALB default action은 403 fixed response로 둡니다.

| Priority | Conditions | Action |
|---|---|---|
| 10 | Header `X-Origin-Verify=wskorea26-cf`, Path `/v1/book`, Method `POST` | EKS target group |
| 20 | Header `X-Origin-Verify=wskorea26-cf`, Path `/reserv-query`, Method `GET` | Lambda target group |
| default | 나머지 | fixed response 403 |

이 구조에서는 CloudFront가 넣어주는 header가 없으면 무조건 403입니다.

### 11.3 Lambda target group

```bash
LAMBDA_ARN=$(aws lambda get-function --function-name wskorea26-book-lambda --query Configuration.FunctionArn --output text)

LAMBDA_TG_ARN=$(aws elbv2 create-target-group \
  --name wskorea26-lambda-tg \
  --target-type lambda \
  --query TargetGroups[0].TargetGroupArn \
  --output text)

aws lambda add-permission \
  --function-name wskorea26-book-lambda \
  --statement-id allow-alb \
  --principal elasticloadbalancing.amazonaws.com \
  --action lambda:InvokeFunction \
  --source-arn ${LAMBDA_TG_ARN}

aws elbv2 register-targets \
  --target-group-arn ${LAMBDA_TG_ARN} \
  --targets Id=${LAMBDA_ARN}
```

### 11.4 EKS target group

AWS Load Balancer Controller를 쓰면 Ingress로 ALB를 만들 수 있습니다. 다만 Lambda target group까지 한 Ingress에서 모두 구성하는 것은 복잡하므로, 시험에서는 다음 중 하나를 선택합니다.

- 방법 A: ALB Controller로 ALB와 앱 target group을 만들고, Lambda rule은 CLI로 추가
- 방법 B: ALB와 target group을 CLI로 직접 만들고, Kubernetes NodePort service를 target으로 등록

시간이 부족하면 방법 A가 더 쉽습니다.

Ingress 예시:

```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: book-ingress
  namespace: wskorea26
  annotations:
    alb.ingress.kubernetes.io/load-balancer-name: wskorea26-book-alb
    alb.ingress.kubernetes.io/scheme: internet-facing
    alb.ingress.kubernetes.io/target-type: ip
    alb.ingress.kubernetes.io/subnets: <PUB_C_SUBNET_ID>,<PUB_D_SUBNET_ID>
    alb.ingress.kubernetes.io/listen-ports: '[{"HTTP":80}]'
    alb.ingress.kubernetes.io/conditions.book-svc: >
      [{"field":"http-header","httpHeaderConfig":{"httpHeaderName":"X-Origin-Verify","values":["wskorea26-cf"]}},
       {"field":"http-request-method","httpRequestMethodConfig":{"values":["POST"]}}]
spec:
  ingressClassName: alb
  rules:
    - http:
        paths:
          - path: /v1/book
            pathType: Exact
            backend:
              service:
                name: book-svc
                port:
                  number: 80
```

Ingress 적용 뒤 생성된 ALB ARN과 listener ARN을 확인하고 Lambda rule을 추가합니다.

```bash
ALB_ARN=$(aws elbv2 describe-load-balancers \
  --names wskorea26-book-alb \
  --query "LoadBalancers[0].LoadBalancerArn" \
  --output text)

LISTENER_ARN=$(aws elbv2 describe-listeners \
  --load-balancer-arn ${ALB_ARN} \
  --query "Listeners[0].ListenerArn" \
  --output text)

aws elbv2 create-rule \
  --listener-arn ${LISTENER_ARN} \
  --priority 20 \
  --conditions \
    Field=path-pattern,Values=/reserv-query \
    Field=http-header,HttpHeaderConfig="{HttpHeaderName=X-Origin-Verify,Values=[wskorea26-cf]}" \
    Field=http-request-method,HttpRequestMethodConfig="{Values=[GET]}" \
  --actions Type=forward,TargetGroupArn=${LAMBDA_TG_ARN}
```

Default 403 확인:

```bash
ALB_DNS=$(aws elbv2 describe-load-balancers --names wskorea26-book-alb --query "LoadBalancers[0].DNSName" --output text)
curl -i http://${ALB_DNS}/book
```

기대값은 `HTTP/1.1 403`입니다.

## 12. CloudFront

### 12.1 Origin 구성

Origin은 2개를 둡니다.

| Origin ID | Domain | 용도 |
|---|---|---|
| `s3-origin` | S3 bucket regional domain | 정적 페이지 |
| `alb-origin` | ALB DNS | `/book*` API |

CloudFront Distribution의 `Comment`를 반드시 `wskorea26-concert-cf`로 설정합니다. 채점 스크립트는 Comment로 Distribution ID를 찾습니다.

### 12.2 S3 origin

S3는 직접 접근 금지입니다. OAC를 만들고 bucket policy에서 CloudFront distribution만 허용합니다.

Bucket policy 예시:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "AllowCloudFrontServicePrincipalReadOnly",
      "Effect": "Allow",
      "Principal": {
        "Service": "cloudfront.amazonaws.com"
      },
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::wskorea26-concert-bucket-<NO>/web/main/*",
      "Condition": {
        "StringEquals": {
          "AWS:SourceArn": "arn:aws:cloudfront::<ACCOUNT_ID>:distribution/<DISTRIBUTION_ID>"
        }
      }
    }
  ]
}
```

### 12.3 CloudFront Function으로 URI 보정

`/book`을 내부 경로로 바꾸는 viewer-request function 예시입니다.

```javascript
function handler(event) {
  var request = event.request;

  if (request.uri === "/book" || request.uri === "/book/") {
    if (request.method === "GET") {
      request.uri = "/reserv-query";
    } else if (request.method === "POST") {
      request.uri = "/v1/book";
    }
  }

  return request;
}
```

이 함수는 `/book*` cache behavior의 viewer-request 단계에 연결합니다.

### 12.4 Cache Behavior

| Behavior | Origin | 설정 |
|---|---|---|
| Default `*` | S3 | Viewer protocol policy: redirect-to-https, root object: `web/main/index.html` 또는 origin path `/web/main` + default root `index.html` |
| `/book*` | ALB | Viewer protocol policy: redirect-to-https, allowed methods: GET/HEAD/OPTIONS/POST/PUT/PATCH/DELETE |

ALB origin custom header:

| Header | Value |
|---|---|
| `X-Origin-Verify` | `wskorea26-cf` |

S3 origin custom header:

| Header | Value |
|---|---|
| `wskorea26-s3-access` | 자유 값 또는 `true` |

채점 스크립트는 header name/value 목록에서 `X-Origin-Verify`, `wskorea26-cf`, `wskorea26-s3-access`가 보이는지 확인합니다.

### 12.5 정적 페이지 경로 주의

제공 `index.html` 안의 이미지 경로는 `main.jpeg`입니다. CloudFront 루트에서 `index.html`이 보이면 브라우저는 `/main.jpeg`를 요청합니다. 따라서 다음 중 하나로 구성해야 합니다.

- 방법 A: S3 origin path를 `/web/main`으로 두고 default root object를 `index.html`로 설정
- 방법 B: CloudFront Function에서 `/main.jpeg`를 `/web/main/main.jpeg`로 rewrite

채점 스크립트는 `https://$CF_DOMAIN/main.jpeg`를 직접 호출하므로 `/main.jpeg`가 200을 반환해야 합니다.

## 16. 자주 틀리는 부분

| 실수 | 결과 | 해결 |
|---|---|---|
| CloudFront Comment를 안 넣음 | `CF_ID`가 `None` | Distribution comment를 `wskorea26-concert-cf`로 설정 |
| S3 객체를 루트에 업로드 | `web/main/` 조회 실패 | `web/main/index.html`, `web/main/main.jpeg`로 업로드 |
| `/main.jpeg`가 404 | 정적 페이지 이미지 채점 실패 | origin path 또는 Function rewrite로 `/main.jpeg` 처리 |
| ALB default가 앱 forward | 직접 ALB 접근이 200 | default action을 403으로 변경 |
| CloudFront custom header 누락 | ALB rule 미매칭 | ALB origin에 `X-Origin-Verify: wskorea26-cf` 추가 |
| Lambda가 `/book` GET을 처리 못함 | 조회 API 실패 | CloudFront Function rewrite 또는 Lambda에서 `/book`도 허용 |
| Pod가 addon node에 올라감 | pod 분리 채점 실패 | book deployment에 `nodeSelector: node-type: app` |
| CoreDNS가 app node에 올라감 | addon 분리 채점 실패 | CoreDNS deployment에 addon nodeSelector/toleration 적용 |
| DynamoDB KMS alias 불일치 | KMS 채점 실패 | 테이블 생성 시 `alias/wskorea26-dynamodb-key` 사용 |
| Grafana service 이름이 다름 | URL 출력 실패 | service 이름을 `grafana`, namespace를 `monitoring`으로 유지 |

## 17. 최종 제출 전 순서

1. `mark.sh`를 실행하기 전에 CloudFront 배포 상태가 `Deployed`인지 확인합니다.
2. ECR image scan이 완료되었는지 확인합니다.
3. `kubectl get pod -A`에서 CrashLoopBackOff가 없어야 합니다.
4. `curl http://<ALB_DNS>/book`이 403인지 확인합니다.
5. `curl https://<CF_DOMAIN>/book` POST와 GET을 직접 실행합니다.
6. Grafana URL이 열리는지 확인합니다.
7. 테스트 부하나 임시 Pod를 지웁니다.
